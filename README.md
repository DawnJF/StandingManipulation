# Unitree G1 双手 6-DOF 位姿追踪（MuJoCo 动力学 WBC）

在 MuJoCo 中让 Unitree G1 从站立姿态出发，**双手同时追踪各自的 6-DOF 目标位姿**
（位置 + 姿态），全程双脚固定、不摔倒；腰和腿与手臂一起参与（允许弯腰、下蹲），
不使用强化学习。

- 默认且唯一推荐控制器：`wbc`，500 Hz 动力学全身 WBC
  - 35 DOF 加速度级 QP：浮基动力学 + 双脚 8 点接触力 + 摩擦锥 + CoP 包围盒
    + 关节力矩/加速度限幅；
  - **DCM/CoM 阻尼 + APA 前馈 + 躯干角动量补偿**；
  - **基座姿态、骨盆水平位置、头部水平位置**稳定任务，优先用踝/髋平移而不是
    躯干俯仰来平衡；
  - 支撑脚始终保留全部 8 个接触点，不按瞬时 `ncon` 清零。
- 求解器：`qpsolvers` + `clarabel`
- 目标轨迹：C2 三次样条；评估严格按源数据时钟，不做时间缩放、速度封顶或幅度裁剪
- 结果：16 个场景 **全部原速站立完成**，最高实测手速 **2.37 m/s**
  （`open_door`），含此前失败的 `fast10`、`fast10_dir`、`take01`、`take02`
- 头部稳定性：直立任务头部前后 x 峰峰 **12–65 mm**；弯腰任务（pickup/shelf）
  的 246–293 mm 是任务要求的下探，不是晃动

> 代码里仍保留 `balance`（运动学 QP + 平衡前馈）和 `kinematic`（旧位置伺服）
> 作为调试/回归基线；本文档只报告 `wbc` 的数据。

## wbc 控制器

每 2 ms 求解一次加速度级 QP，决策变量：

```text
x = [q̈(35), f(8×3), τ(29), slack(8×3)]        (112 维)
```

约束：

- 浮基动力学 `M q̈ + h = Sᵀτ + Jᵀf`（35 行）；
- 双脚 8 个接触点 `J_c q̈ + J̇_c q̇ = −s`（24 行，松弛权重 1e7，上限 5 m/s²）；
- 逐点摩擦锥 `|f_x|, |f_y| ≤ μ f_z`（μ = 0.5，4 面），`f_z ≥ 0`；
- 每只脚 CoP 落在 4 个接触球包围盒内（内缩 10 mm）；
- 总法向力 0.65–1.25 倍体重；关节力矩 ≤ 95% 模型上限；关节 q̈ 限幅。

软任务与权重：

| 任务 | 权重 |
| --- | --- |
| 双手位置 | 2.0e4 |
| 双手姿态 | 1.0e5（Kp=800 / Kd=80） |
| CoM 水平 | 1.0e6 |
| CoM 竖直 | 2.0e3 |
| 骨盆高度 | 5.0e2 |
| 骨盆水平位置 | 2.0e4 |
| 基座姿态 | 2.0e3 |
| 躯干姿态 | 3.0e3 |
| 头部水平位置 | 1.5e4 |
| 关节姿态先验 / 速度阻尼 | 20–100 |

### 平衡层

```text
com_ref = com_base + k_apa · (m_arm/m_total) · (h_com/g) · a_hand(t + 0.15 s)
a_com   = ω² (com_ref − com) − 2ζω v_com,   ω = 3.2, ζ = 0.9
torso  += −k_θ · (a_right − a_left)/2,      k_θ = 0.02
```

- `k_apa = 0.6`，`m_arm` 为两条肩部子树实测质量（G1 为 8.09 kg，占整机 23.4%）；
- 躯干补偿吸收双手反向/对角运动产生的净角动量；
- 基座姿态 + 骨盆水平位置任务阻止“用屈膝把骨盆平移出去够目标”的伪策略。

### 头部稳定

G1 没有颈关节，头是 `torso_link` 上的固定点，所以“头部前后晃”主要是基座平移 +
躯干俯仰。`wbc` 的头部水平任务直接约束头点前后/侧向加速度，并配合基座姿态任务
让平衡优先走踝/髋平移。

- 直立任务：头部水平参考锁在初始位置；
- 躯干前倾超过 20° 的任务（`pickup` / `shelf`）：平滑过渡到离线规划的头部轨迹，
  避免为了“锁头”破坏必要弯腰。

### 接触建模

支撑脚始终保留全部 8 个接触点力变量，不按 MuJoCo 瞬时 `ncon` 清零。否则脚跟一旦
离地，该点的力被永久置零，CoP 无法回到脚跟，卸载会自增强并直接翻倒。实测 `demo`
的 `ncon` 最低为 2，机器人仍站立——QP 使用的是支撑脚全脚力变量，而不是当前接触列表。

### 力矩接口

QP 求出的 τ 通过位置伺服反解：

```text
ctrl = q + (τ + k_v q̇) / k_p
```

再按关节范围裁剪。不要在 `apply()` 里额外扣关节力矩阻尼：腕部只有 5 Nm 上限，
额外 `2·q̇` 会吃掉大部分力矩，导致手姿态滞后 20–45°。QP 内部已有独立的关节速度
阻尼任务。

## 三个实现陷阱

1. **CoM 任务的 `J̇q̇` 数值差分**在 500 Hz 下噪声过大，会破坏闭环。去掉该项后，
   `take01` / `alternate` / `fast08` 才从摔倒变为完成。
2. **关节力矩阻尼 `WBC_TAU_DAMP=2`** 会吃掉腕部 5 Nm 中的大部分，导致手姿态
   滞后 20–45°。置零后姿态误差恢复到 2–3°（`take03` 仍有 0.6 s 腕部饱和瞬态）。
3. **手部任务压过 CoM** 时，WBC 会用屈膝/踝把骨盆整体平移去“够”目标，CoM 越界后
   慢速后倒。把 `W_COM` 提到 1e6 后该策略消失。

## 数据完整性

- 控制器评估严格按源数据时钟执行：`tt += dt`，**不做时间缩放、速度封顶或幅度裁剪**；
- 16 个场景的速度是场景定义的一部分（`scenarios.py`），不是运行时为了让控制器通过
  而临时降速；
- `take01–03` 保留 FBX 原始时序（2.96 / 2.96 / 2.46 s）；重定向所需的几何变换
  （位置比例 ~0.97、腕部可达范围、肩点径向裁剪）记录在 `data/retarget/*.npz`
  与 `--list` 中；
- 诊断用慢速版本必须单独命名，不能混入正式 bench；
- 失效（摔倒、QP infeasible、足端滑动、几何穿透）必须如实报告——当前
  `wave` / `converge` / `shelf` 仍有毫米级穿透，见上表。

## 已知限制

1. **`shelf` 在当前速度下有 25 mm 几何穿透（0.68 s）**，RMSE 53.1 mm。这是
   2.7 s 内完成 39° 前倾 + 2.0 m/s 单臂深伸时，实际动力学轨迹比规划更靠近身体；
   WBC 没有显式碰撞避让。控制器仍然站立，但不应把这组数据当作“无碰撞通过”。
   `wave`（−2.12 mm）和 `converge`（−0.49 mm）也有轻微穿透。
2. **腕部 5 Nm 力矩上限**：`take03` 快速手腕翻转有 0.6 s 饱和，姿态 RMS 7.36°；
   再提高旋转权重会让 `take03` 失稳，因此保留这个物理限制。
3. **关节 jerk 较高**：力矩级控制 + 硬接触使关节 jerk 高于位置伺服基线
   （`demo` 7452 rad/s³）；头部/末端运动仍平滑。若需要更低 jerk，需要增加力矩
   变化率惩罚。
4. **固定双脚、无踏步**：当前 16 个场景都在双脚不动的前提下完成；更大范围伸取
   或更强扰动仍需要踏步/落脚规划。
5. **实时性**：单进程仿真实时因子约 0.50，WBC 求解 2.32 ms/步（p95 2.60 ms）。
   真机 500 Hz 部署需要控制器分核/实时线程；并行 bench 时的求解时间会被 CPU
   争用放大，不能作为实时性指标。

## 方法概要

1. **目标轨迹**：场景关键帧经 C2 三次样条生成双手位置/姿态、骨盆高度、躯干姿态；
   FBX 动捕经几何重定向到 G1（比例 ~0.97、腕部可达范围、肩点径向裁剪），保留原始时钟。
2. **离线规划（前馈参考）**：500 Hz 浮动基座全身 IK/QP，生成关节/基座轨迹；
   用于 WBC 的头部/骨盆前馈参考和指标对照，不是最终控制指令。
3. **在线 WBC**：500 Hz 求解 `q̈ + 接触力 + τ` 的 QP，输出 29 个关节力矩，
   经位置伺服反解为 `ctrl`。
4. **物理仿真**：MuJoCo 3.3，2 ms 步长，模型碰撞全程开启。

## macOS 说明

MuJoCo 的被动窗口必须由 `mjpython` 启动。直接运行 `python -m g1_wbc.live` 时脚本
会自动 `exec` 切换到同目录下的 `mjpython`，无需手动敲。若本机 Xcode 许可未接受，
`mjpython` 会因 `/usr/bin/otool` 报错而崩溃，脚本会自动把
`/Library/Developer/CommandLineTools/usr/bin` 前置到 `PATH` 规避。
